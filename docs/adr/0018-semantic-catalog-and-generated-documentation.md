# 0018. Semantic catalog + generated documentation: describe assets where they're built, publish where they're read

- Status: accepted
- Date: 2026-08-11

> Extends ADR-0014's asset model with the descriptive fields a human (or an
> agent) needs to use a table without having built it. Settled in
> conversation, prompted by an external framing of "open lakehouses as public
> research infrastructure" and its relevance to bioc-on-ice/icegate — the
> deliberation is preserved as the decisions below.

## Context

ADR-0014 specified `lake_ops.asset` (typed, owned, ref'd) but the entity
hasn't landed yet — today's metadata is table/column `COMMENT ON` (models.py's
`-- description:`/`-- license:`/`-- column <name>:` directives, landed in
PR #50) plus `ops.SOURCES`' `writer`/`cadence` and per-run provenance in
`lake_ops.run`. That covers *what a column means* and *who owns it*, but not
*what a table is for*: nothing records a model's grain, its primary key, or
whether it's append-only, upsert-latest, or full type-2 history — that
knowledge exists only in the SQL and the author's head. There's also no
convention for "questions this table answers" — `models.py`'s `.test.sql`
sibling files assert correctness, not usefulness.

Separately, bioc-on-ice (ADR-0012 there: "cdsci-lake is the source, not raw
upstream") is heading toward being public research infrastructure — a
scientist who didn't build the pipeline needs to find, understand, and cite a
table. That downstream need doesn't belong in cdsci-lake (this repo has no
public audience; bioc-on-ice does), but the metadata it would consume mostly
already exists here, one layer short of exposed.

## Decision

**Describe assets with a few more typed fields at the point they're defined;
generate documentation from that plus what `ops` already records; stop there
— citation, search, and a public site are bioc-on-ice's job, not this
repo's.**

1. **Three new model directives**, parsed the same way as `-- description:`
   (`models.py:42`), no new file format:
   - `-- grain: <sentence>` — e.g. "one row per (source, gene_id)".
   - `-- primary_key: <col[, col...]>` — usually redundant with `upsert`'s
     `key=`, but `key` is a runtime call argument today, not a queryable
     fact; this makes it one.
   - `-- temporal_model: append | upsert_latest | scd2` — names the pattern
     already implicit in whether a model re-derives from raw each run or
     merges. No new mechanism, just naming what's already true per model.

   Same lifecycle as `description`/`license`: parsed into `Model` (`models.py`
   dataclass), attached to the table via `COMMENT ON TABLE` as a structured
   suffix (JSON in the comment, matching how `ensure_column_comments`
   already treats comments as the durable store) rather than a new
   `lake_ops` column — cheaper than waiting on the `asset` table, and
   upgrades cleanly to real `asset` columns once ADR-0014's skeleton lands.

2. **An `examples/` convention, mirroring `.test.sql`.** A model
   `models/bugsigdb/signature.sql` may have a sibling
   `models/bugsigdb/signature.examples.sql`, header-commented per example:
   ```sql
   -- question: Which taxa are implicated in a given disease signature?
   SELECT ...
   ```
   Parsed the same way `.test.sql` splits test blocks (`models.py:87-100`).
   **Examples run in CI** alongside model tests (`runner.py`) — an example
   that stops executing is a broken doc, caught the same way a broken test
   is, not discovered by a reader.

3. **`transform docs` CLI command** (new subcommand in `transform/__main__.py`,
   next to `run`/`test`/`publish`) that walks `load_models()` +
   `ops.list_sources`/`list_runs` + `connect.snapshot_log()` and emits one
   markdown file per asset to `docs/catalog/<schema>/<table>.md`: description,
   grain, primary key, temporal model, column comments, last-run
   provenance (source, version, snapshot id, timestamp), and any examples.
   **Generated, not hand-maintained** — same reasoning as `COMMENT ON`
   already being the source of truth instead of a wiki page. Committed to
   the repo (small, diffable, reviewable in PRs) rather than built at
   request time — there's no server to host a live-generated site from yet.

4. **Provenance becomes a documented read, not a new capability.** `ops.run`
   already records source/version/snapshot-before/after per run
   (`ops.py:410-419`); `transform docs` just projects it per-asset instead of
   per-run. No new table, no new write path.

## Consequences

- Closes the gap named in conversation: grain/key/temporal-model are now
  facts a query (or a future `asset` table) can carry, not tribal knowledge.
- `docs/catalog/` becomes generated output, regenerated by CI on model
  changes (same job that runs `transform test`) — drift between docs and
  reality is a CI failure, not a stale wiki.
- Examples executing in CI is the same principle ADR-0015 already applies to
  models: the file is truth because it's the thing that runs.
- **This is explicitly not** a documentation *site*, a search index, a
  citation generator, or an MCP server. Those are real, named ideas from the
  same conversation, and they're bioc-on-ice's (or a later cdsci-lake ADR's)
  job once there's a public reader to build them for — cdsci-lake's job here
  is only to make sure the data those would need (description, grain, key,
  temporal model, provenance) exists and is queryable at the source, per
  bioc-on-ice ADR-0012's "cdsci-lake is the source" split.
- **Cost:** three more directives to keep populated per model (mostly a
  one-time backfill across ~15 existing models), and `transform docs` is new
  surface with its own test (per the repo's "non-trivial logic gets one
  runnable check" convention).
- Still owes a real decision on where `grain`/`primary_key`/`temporal_model`
  live once `lake_ops.asset` (ADR-0014) actually lands — comment-embedded
  JSON is the cheap interim, not the final shape. Flagged, not blocking.

## Alternatives considered

- **A YAML sidecar per model** (the shape floated in conversation, e.g.
  `models/bugsigdb/signature.yml`). Rejected — it's a second file to keep in
  sync with the SQL, the exact failure mode `COMMENT ON`-as-source-of-truth
  already avoids for description/license; a directive line costs the same to
  write and can't drift from the model file it's inside.
- **Build the docs site / semantic search / citation layer now, in this
  repo.** Rejected — no public audience at the cdsci-lake layer yet (that's
  bioc-on-ice), and ADR-0012/0015's pattern throughout has been "narrowest
  thing the real, current need justifies." Premature here for the same
  reason a SQLMesh-style gateway config was premature in ADR-0012.
- **Wait for `lake_ops.asset` (ADR-0014) before adding any of this.**
  Rejected — the asset table isn't blocking; comment-embedded metadata is a
  cheap, reversible interim that upgrades to real columns later without a
  migration of the *models* (only of where `transform docs` reads from).
